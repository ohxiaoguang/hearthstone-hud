# v0.1.1 Python 后台导入修复与测试

## 根因与变更

Decky sandboxed_plugin.py 仅将插件 py_modules 添加到 Python 搜索路径，再通过文件路径加载 main.py。v0.1.0 将 engine 放在根目录，在设备上出现 ModuleNotFoundError，尚未执行 _main。

参考：https://github.com/SteamDeckHomebrew/decky-loader/blob/main/backend/decky_loader/plugin/sandboxed_plugin.py

本版本仅将打包后的 engine 映射为 py_modules/engine，校验 __init__.py/io.py/power.py 必须存在，保持源码目录和 main.py 导入不变。engine.io、engine.power 只引用标准库，无需变更内部导入。C++、Gamescope、炉石日志解析代码均未修改。

## 本地结果

2026-11-14，macOS ARM64 / Python 3.9：

- npm run typecheck：通过。
- npm run build：通过，生成 dist/index.js。
- npm test：9 项通过，保留原有所有测试。
- 新增打包结构测试实际执行 package.py，然后解压其输出 ZIP。检查 py_modules/engine/__init__.py、io.py、power.py，拒绝旧 engine 根目录布局。
- 独立 Python 使用 -I -S，排除当前目录、PYTHONPATH 和 site-packages，只追加解压后 py_modules。注入仅用于模块加载的 decky 替身，确认 engine.io、engine.power 来自该解压目录，main.py 正常导入。该测试不声称已执行真实 Decky 后台生命周期。
- 单元测试的 ELF 头仅是临时结构夹具，不作为发布产物。发布 ZIP 必须来自 Actions 的真实 Linux 编译。

## CI 验收

工作流继续执行前端构建、全部 Python 测试、Ubuntu x86_64 原生编译、ELF64 架构与可执行格式检查、ldd、readelf/GLIBC <= 2.31 检查及安装 ZIP 打包。新增 verify-decky-zip.py 步骤位于打包之后、artifact 上传之前，针对真实最终安装 ZIP 执行隔离导入；失败禁止上传。

实际 CI 运行状态与链接见对应 v0.1.1 Release，本文不预先声称尚未执行的 CI 已成功。
