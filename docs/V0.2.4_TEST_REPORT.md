# v0.2.4 控件与 CA 修复

实机输入：v0.2.3 对局/双方身份、同会话 Power/Decks、完整初始牌组及 36390 张 zhCN 离线数据库已识别；1285 条接受事件，解析错误 0。22 行剩余量全部未知；图片缓存为 0，下载返回缺少本地签发者的证书验证错误。用户照片确认 HUD 显示、简体中文名称与 QAM 面板存在，原生 HTML 折叠箭头无法展开。

实现：

- 原生 HTML details/summary 换成 Decky ButtonItem，React 状态控制内容显示，沿用已工作的按钮交互。
- 标准库严格 TLS 上下文读取常见系统 CA，并加载随插件打包、固定官方提交的 Mozilla/certifi CA 数据。无 pip/Homebrew 安装，无系统或全局环境修改。
- 用户后续明确授权先跳过校验做测试，因此增加仅影响卡图下载的“卡图 SSL 证书校验”开关，本测试包默认关闭。数据库仍严格验证；开关打开后卡图恢复使用上述 CA 上下文。PNG/CRC/尺寸检查不受影响。诊断标记 Image Verification disabled/testing，避免假称正在验证。
- 诊断增加有效 CA 数量与来源、初始实体/缺失实体/未知非初始在库实体和逐卡未知原因。没有真实 Power 日志文件，不能断言 22 行全未知的唯一原因；计数公式未放宽、不推断隐藏身份。
- 原生 C++、Overlay、Gamescope、焦点与触控代码未修改。

本地验证：57 项 Python 测试通过，包括空默认信任库加载内置 CA、完全无 CA 时拒绝继续、卡图测试模式不影响数据库严格验证、计数证据统计。保留已有测试，并确认展开控件使用 Decky 按钮而不再存在 details/summary。4 条剪贴板路径、类型检查和前端构建通过。Linux 原生编译、ldd/readelf/GLIBC 和最终 ZIP 验收由 Actions 完成，实际状态见 Release。

未验证：Ally X 的新展开/收起、网络实际信任链恢复、计数未知的真实原因和卡牌特殊机制。新的诊断能说明具体代码分支，但不能代替设备日志回放。
