## 依据与修复

参考 hs-decktracker-linux 649534be99f35cb499ed2fae371625bd04b95b1d 的 paths.py 与 decks.py：Decks 单独使用 LogLevel=1、FilePrinting=True、ConsolePrinting=False、ScreenPrinting=False、Verbose=False；牌组打印块包含 Finding Game With Deck / Starting Arena Game With Deck、注释行及 AAE... deck code。启用节后应重启并选卡组排队，不能把文件存在等同于已经记录完整牌组。

1. 新增显式“备份并启用 Decks 日志”按钮，仅当前进程前缀生效。默认只检查，不静默开启。共用已有备份/并发变更检查/原子替换流程，只改 Decks，保留 Power 和其他日志节。记录写入进程实例，重启前持续提示；不覆盖用户后续配置，不改 client.config。
2. Power/Decks 只关联同一日志目录。修复新 Power 会话继承 Decks 旧读取游标的问题，以及队列时间早于开局但跨文件迟到的代码未绑定问题。只补绑定缺失的牌组，不用未来代码替换当前对局。无 Decks/数据库时继续展示 Power 确认的 CardID 和已知实体，初始/剩余数量未知不填充。
3. 数据库保持默认 SSL 证书与主机名验证，每次最多两次 HTTPS 尝试。无缓存时后台定期重试，支持手动重试。新增官方 zhCN JSON 离线导入：64MiB 上限、结构/ID/重复项/类型验证、至少 100 条有效卡牌后原子替换。失败保留旧缓存；较旧下载不能覆盖更新的离线导入。缓存加载同样校验。数据库错误与卡图错误分开显示。
4. 诊断分别呈现日志读取、对局识别、双方身份识别、完整牌组、数据库可用性；显示 Decks 配置/文件、候选代码数量与解析错误、数据来源/时间/下载状态。
