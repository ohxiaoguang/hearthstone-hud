# v0.2.6 实体标签去重与布局修复

## 已确认根因及真实回放

用户提供的真实 Power.log 中，多张实体使用同一纳秒时间戳初始化，多个记录内的 tag=ZONE / tag=CONTROLLER 行可以完全相同。v0.2.5 用完整原始行作为全局去重键，错误丢弃不同实体的相同标签。该问题可以同时造成控制者丢失、开局实体不属于我方、抽牌/出牌漏记，而不触发语法错误。

修复后：缩进 tag 行使用“原始行 + 所属实体记录 ID”作为键；重复记录也先恢复输入上下文再判断重复，避免回放后把新标签应用到错误实体。无关日志流不清除有效 GameState 记录上下文。完整记录、重复出牌行继续去重，最近 8192 条窗口不变。

附加兼容：读取方括号实体描述中的 player / zone / cardId，仅补缺失值，显式标签优先；CONTROLLER=0 不定案，保存 setup 时已进入 DECK 的证据，之后确认控制者时保留原牌身份。不会根据卡组代码或历史前缀猜实体归属。

本地真实日志回放结果（只记录匿名聚合，不提交原文件）：

| 截止同一时刻的状态 | v0.2.5 | 修复后 |
| --- | --- | --- |
| 实体数 | 84 | 84 |
| 无控制者实体 | 57 | 1（GameEntity） |
| 己方原始实体数 | 0 | 30 |
| 己方出牌事件 | 3 | 6 |
| 解析错误 | 0 | 0 |

完整文件回放识别 8 个游戏记录，最后一个记录识别到 30 个己方原始实体，88 个实体只有 GameEntity 不需要控制者，解析错误 0。前面的记录也恢复出 30/40 张原始牌组实体。此处截止时刻与用户诊断采样略有差异，因此不把事件数量差异当作用户截图的逐事件真值。

用户没有提供同会话 Decks.log，本次真实回放只验收 Power 实体、归属、区域与出牌状态；完整牌组定义与当前局关联、剩余数量数值使用格式回归样本验证，不声称完整真实联合回放已通过。原始日志只读处理，未复制进项目、未导出玩家姓名/账号。提交的两个新 fixture 使用替代 Card ID、匿名玩家和零账号，重建最小格式案例，不含原始对局数据。

## 布局和选项

- 右侧独立己方剩余牌库（原牌与当前在库的后加入牌），不混入任何出牌记录。
- 左侧上方对手已打出、下方我方已打出，各有独立开关。两者开启平分可用高度；只有一个则使用全部高度；均关则左侧为空。
- 顶部信息独立开关；面板宽度 180–640，随缩放并受屏幕边界约束，左右位置仍可调。
- 原牌 remaining=0 默认置灰；开启“隐藏已耗尽原牌”后隐藏。remaining=null 永远不按零隐藏。
- 继续使用 8 秒自动分页，只依据各面板实际可用高度计算容量。卡图底图和来源说明保留。Gamescope、XShape、焦点、触控穿透、父进程退出、显示协议均不改。

## 缓存与卸载

缓存来自 `DECKY_PLUGIN_RUNTIME_DIR/cache`，界面和诊断报告实际路径。默认：

- 数据库：`/home/deck/homebrew/data/hearthstone-hud/cache/cards.json`
- 自动图片：`/home/deck/homebrew/data/hearthstone-hud/cache/images/`
- 手动图片：`/home/deck/homebrew/data/hearthstone-hud/cache/images/manual/`

插件 `_uninstall()` 不删除数据。Decky 当前官方卸载实现删除 plugins 下的安装目录，没有清除独立 data 目录；因此正常更新/卸载保留缓存，重装可继续使用。用户自己导入的源 JSON / ZIP 路径同样不删除。只有手动删除对应 data 目录等额外清理才会清空缓存。

目录/卸载依据：[Decky sandboxed_plugin.py](https://github.com/SteamDeckHomebrew/decky-loader/blob/main/backend/decky_loader/plugin/sandboxed_plugin.py)、[browser.py](https://github.com/SteamDeckHomebrew/decky-loader/blob/main/backend/decky_loader/browser.py)。
