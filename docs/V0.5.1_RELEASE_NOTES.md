# Hearthstone HUD v0.5.1

竞技场恢复修复版。安装文件：`hearthstone-hud-0.5.1.zip`。

## 安装

1. 在 Decky 中安装 `hearthstone-hud-0.5.1.zip`（或把本 Release 的 ZIP 直链填入 *Install Plugin from URL*）。
2. 新安装默认关闭“竞技场辅助”（只读内存）；在 Decky 里主动开启。普通记牌不需要内存。
3. 首次使用会后台下载 zhCN 卡牌数据库与当前牌组/候选的卡图；失败可重试。

## 本次修复

- **中途接入恢复不再被日志门控**：历史恢复此前只在 Arena.log 追平时执行。日志未追平、文件陈旧或本轮无新日志时，只读内存快照仍会按两次一致读取建立基线，Recovered History 不再恒为 0。
- **锚点改为内存读取窗口**：同时记录首个牌组读取之前的下界与复读校验之后的上界。日志事件时间早于/等于下界 → 并入历史；晚于上界 → 计为新选牌（重复 Card ID 逐次计）；落在窗口内或缺少时间戳 → 不猜测，单独计数并标记 `Uncertain Picks`，界面显示“份数待确认”，内存下一次刷新后自动收敛。修正了“第二次读取之后打点”导致的同卡新选牌被当成历史（少算一张）。
- **牌组解析与候选识别隔离**：`m_slots` / `m_cardId` / `m_count` 的结构异常只放弃本次牌组（不发布部分牌组、写明确原因码），三张候选照常显示；区分字段缺失（`no_count_field`）与 null（`null_count`，按上游 0 份语义）；超 40 份整体拒绝，不截断不补齐。未修改任何 Mono 偏移或类名。
- **诊断可定位**：`[Arena Recovery]` 输出 Merge Executed / Recovery Executed / Memory Deck Size / Deck Object / Slot Count / Covered Copies / Deck Reason / Snapshot / Snapshot Window / Snapshot Size / Recovered / Pending / Uncertain / Logs Caught Up / Recovery Reason（原因码 + 中文）。
- **合并修正**：手工补录被日志确认（同轮同卡）不再清空已恢复历史；锚点之后到达的日志记录不再被丢弃。

## 验证范围

- 合成验证：216 项 Python 测试通过（含中途接入、迟到日志、重复卡牌、后续选牌、日志去重、读取窗口竞态、牌组结构变体、重选替换、ID 冲突）；前端类型检查与构建通过；Linux 原生渲染器与打包由本 Release 对应的 Actions 构建。
- **尚未实机验收**：SteamOS / Ally X 上的真实 Mono 布局、内存读取耗时（`Snapshot Window` 数值）、QAM 显示与触控仍以设备结果为准。本 Release 标记为 Pre-release。

## 已知限制

- 只支持 Unity 6000.3 x64 / `mono-2.0-bdwgc.dll` / Assembly-CSharp；布局不符时报告不兼容并保留日志与手动功能，不尝试其它偏移。
- 日志时间与系统时钟需同源；时间不可比时相关记录会落入“无法判定”，不会被静默吞掉。
- 内存不可用且日志不完整时，仍不会补出未确认的牌；历史顺序始终标记为未知。
