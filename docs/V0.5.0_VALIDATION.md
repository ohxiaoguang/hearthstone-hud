# v0.5.0 验证与实机验收

## 实现边界

总开关 persisted enabled=true，停用保留 visible、arena_memory 等偏好。控制 RPC 通过生命周期锁串行化。日志循环和媒体 worker 使用停止信号协作退出，所有后台 I/O 使用插件自有 ThreadPoolExecutor；停用等待在途任务结束、join 内存线程、shutdown(wait=True) 线程池，并终止/回收渲染子进程。不会修改 Decky 的共享线程池或其他插件。

页面区分 starting/running/stopping/disabled。在途下载退出前显示 stopping；停用完成后不再轮询状态，重新启用仍可通过设置 RPC 执行。总开关关闭不等于 HUD 偏好关闭，也不清空历史数据。

ArenaRecovery 独立于 Arena.raw_choices：两个不同 observed_at 的一致牌组快照建立数量基线；日志记录与历史快照按复制数量核对，后续事件单独保留。内存增量与后到日志持续核对，内存不可用时继续依据新日志推进，避免同一张卡重复计数；历史记录没有可证实顺序，明确使用 memory_history、round=0、order_known=false。尚待内存确认的日志增量保留为待核对数量，不冒充精确快照。当前阶段最终 Decks 定义覆盖恢复数据，重选前的旧最终定义不会覆盖当前重选快照。

## 自动化覆盖

- 关闭后日志/媒体任务及自有线程池全部退出；内存 reader 关闭；关闭期间不解析新增日志、不继续扫描。
- 在途卡图下载未结束时，停用 RPC 不提前成功；退出后缓存文件保留。
- 保存 disabled 后重新加载不创建扫描、媒体或内存任务；启用后恢复先前 HUD 与显示设置。
- 停用时拒绝启动 HUD、重试数据库、下载图片和清理缓存；反复关闭幂等。
- 中途恢复复制数量；已确认日志与历史分组；候选不计入，历史不造轮次。
- 同 Card ID 后续选择；日志先到、内存先到、重复日志；内存失败后的日志推进。
- 重选替换、被移除的旧牌、旧阶段最终牌组、新阶段 Decks 最终覆盖。
- 数据库迟到、进程重新连接、独立快照要求、快照期间复制数量变化拒绝发布。
- 最终 ZIP 必须包含 arena_recovery.py，并在隔离搜索路径中导入。

本地运行 npm run typecheck、npm run build、npm test；Linux 原生状态测试、编译、ELF/ldd/readelf/GLIBC 和最终 ZIP 检查由 Actions 执行。结果见对应发布的 Actions 运行，不以 Mock 测试代替设备结果。

本地结果：170 项 Python 测试通过（原 151 项，新增 19 项）；前端类型检查、构建、剪贴板与折叠控件检查通过。原生状态测试新增历史分组结构校验，由 Actions 执行。

## Ally X 实机步骤

1. 启动正常对局、开启 HUD 与竞技场辅助；记下字号、宽度等偏好。
2. 下载过程中关闭“启用插件”：等待停用完成，确认窗口消失，复制诊断中的 Background 全为 false、Lifecycle=disabled，内存 fd 和插件渲染进程已释放。退出/重开设置页仍保持停用。
3. 再次开启，确认之前的 HUD、竞技场和显示偏好恢复，日志从上次位置继续，配置与缓存没有丢失。
4. 竞技场已选 10–15 张时开启插件/竞技场辅助，核对 X/30 与逐份卡牌。缺失顺序的部分应显示为“内存历史 · 顺序未知”。
5. 继续选择几张，包含重复 Card ID，确认每次只增加实际选中的卡牌；内存刷新或重复日志不能再加一次。
6. 完成牌组，确认当前 Decks.log 的最终 30 张及复制数量覆盖恢复结果。验证地下模式与重选时被替换的牌不残留。
7. 内存权限不足或游戏退出时确认仍可使用日志；不修改系统权限。检查普通对局计数、QAM 共存、触控穿透和 HUD 显示。

尚未实机验证：新总开关资源回收、SteamOS 在途网络请求关闭时延、中途恢复/重选以及本版分组显示。无法从不完整日志还原历史选择顺序；读取布局仍受已有 Unity/Mono 兼容性限制。
