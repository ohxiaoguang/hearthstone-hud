# v0.2.1 运行时 Proton 前缀与 Power 配置修复

用户确认真实 Hearthstone.exe 使用的 compatdata ID 与旧默认值不同。根因是保存/默认前缀不能代表当前正在运行的游戏环境，而真实前缀没有 log.config。

## 变更边界

新增 engine/proton.py：扫描 /proc 数字 PID，以 comm、可执行参数识别 Hearthstone.exe，排除 Python/HUD 等仅提及该名字的进程。只为匹配的游戏读取环境，仅保留 WINEPREFIX、STEAM_COMPAT_DATA_PATH、SteamAppId。先选择有效 WINEPREFIX，再尝试 compat data/pfx；均要求绝对路径、目录存在且具有 drive_c。没有游戏进程、环境不可读、前缀/用户不唯一时明确报告，不使用历史配置。Z: Windows 绝对路径还原为 Linux 路径，失败保留用户 game_dir。

新增 engine/logconfig.py：只处理当前进程对应的实际 Windows 用户目录，不依赖固定 steamuser 名称。仅写 Power 五个所需键，保留无关配置和注释；已有文件备份精确原始字节，临时文件 fsync 后原子替换，权限 0600。已满足要求时不改写；解析异常、软链接、路径逃逸或并发用户修改会拒绝覆盖。不会写 Decks、options、client.config、旧前缀或 SteamOS。

后台保存配置写入对应的进程实例与路径，跨插件重载保留“完全退出并重启炉石”提示，检测到新的游戏进程实例后解除。诊断脚本只读，读取同一发现模块和自动配置记录，无需 --prefix。不再提供历史前缀编辑框；原设置保留兼容但不参与自动配置。

状态区分：游戏未发现、Proton 前缀未发现、log.config 不存在、Power 未启用、Power.log 未生成、已生成暂未更新、正常读取。游戏 Logs 与前缀发现独立，原有有界扫描/轮转/活动判断不变。

## 必要验证

- 5 项新模块基本测试通过：WINEPREFIX 优先、compat data 回退/末尾斜杠、Z: 路径还原、自定义 Windows 用户、无游戏/无有效前缀/多用户不猜测、配置新建、原始字节备份、其他配置保留、幂等及诊断状态。
- Python 语法检查、TypeScript 类型检查和前端构建通过。
- CI 保留现有测试、Linux x86_64 构建、ELF/依赖/GLIBC 检查、最终 ZIP 解压导入验收。最终运行链接与状态见 v0.2.1 Release；不在本地模拟完整 SteamOS 或游戏。
- PowerParser、DeckLog、卡牌数据库/缓存、C++、Overlay 协议与输入穿透均未修改。

## 用户设备验收

尚未经过 ROG Ally X 实机验证。安装后启动炉石，检查 PID、运行时前缀、配置路径与 Power 状态；首次配置写入后必须完全退出并重启炉石，随后开始一局检查 Power.log。插件不强制重启。只启用 Power，不额外改 Decks；如缺少完整牌组，仍显示部分已知/未知。
