# v0.2.0：日志记牌与 HUD

## 审计与实机边界

用户确认 v0.1.x 在 Ally X 游戏模式下 HUD、中文、PNG、触控和 QAM 关闭后显示正常。本版沿用窗口创建、GAMESCOPE_EXTERNAL_OVERLAY、XShape 空输入区域及无焦点属性；仅扩展 HUD 内容渲染。不改 Steam/BPM/系统/游戏配置，不导入内存模块。

旧日志发现仅支持 Logs 和下一层，精确大小写且不接受文件；还会把最近的旧文件当成活动日志。真实设备漏检的具体目录和日志配置目前不可访问，因此不能断言唯一实机根因。进程名称只匹配 gamescope 会漏掉 gamescope-wl；新版匹配 gamescope-* 及可执行文件名，检测不到显示“未确认”，不会阻止 HUD。

**未用 Ally X 实机日志回放验证。** 测试基于 hs-decktracker-linux 649534be99f35cb499ed2fae371625bd04b95b1d 已确认的 GameState/Decks 格式生成合成样本，测试卡牌名称为合成数据。新版本真实记牌成功仍需用户安装后验证。

## 实现

- 限定游戏 Logs/logs 或手动目录/Power.log，扫描深度 6、最多 1024 目录、3 秒一次，不扫描整个 home、不追踪目录软链接。
- 选择最新 Power.log 及同目录 Decks.log；5 分钟无更新不回放。后台每 250ms 读取最多 1MiB 完整行，支持 inode 替换、截断、原地重写。积压未读完前不显示历史对局。会话日期与午夜 rollover；时间戳+完整内容去重（最近 8192 行），只解析 GameState，不解析动画重播。
- 保留原 MIT PowerParser；独立 Tracker 派生类记录实体抽取、实际出牌身份和公开身份；DeckLog 使用已确认的 Finding Game With Deck / Starting Arena Game With Deck 及 deck code，按时间绑定到游戏，不把已出牌当完整牌组。
- 初始完整牌组、当前区域身份、抽过的原始实体、实际使用次数分开存储。生成/复制不扣原始卡组；洗回通过实体当前区域恢复；变形保留原始身份和当前身份；当前牌库总数由实体区域计数。出现未知离库卡或实体记录不完整/数据库缺少 dbf 映射时，逐卡剩余量标为未知，HUD 的 >=n 只代表可确认当前在牌库里的 n 张。
- 对手公开数量按实体+公开身份去重，同一实体变形可出现在两个身份行中，不代表两张原始牌。未知已使用实体用占位符，不揭示隐藏手牌身份。
- zhCN 元数据 7 日缓存，下载失败保留可用缓存并显示 ID；图片单工作线程按需下载，队列 128、单图 1MiB、最大边长 1024、磁盘 256 张/32MiB；每个图片失败至少等待一小时重试。原生纹理缓存 128 项，避免每帧重新解码。缓存不随安装包分发。
- 左右面板和顶部信息；位置、透明度、缩放、左右显示、卡图和中文开关实时生效；列表太长每 8 秒自动翻页。原生渲染只消费 JSON，不执行日志解析。

## 测试

本地实跑结果：26 项 Python 测试通过（v0.1.1 的原有测试均保留），TypeScript 类型检查、前端构建、Python 编译与 Bash 语法检查通过。

覆盖：TypeScript 严格类型检查、前端构建、Python 单元/集成测试、Python 编译检查和脚本语法检查。覆盖：已确认格式 Power/Decks、卡组初始化、抽/出牌、生成/复制、洗回、变形、对手公开与未知、重连、重复行、新对局、结束、截断/替换、中文映射、无数据库/离线、缓存与图片限制、午夜日期、真实后台发现到 IPC、最终 ZIP 导入。

修复中发现并纠正：Python 3.9 的 asyncio.Queue 在同步测试中绑定事件循环问题（改用标准库线程安全队列）；修改路径与后台扫描并行时旧扫描结果覆盖新设置的竞态；生成牌离开牌库后行消失导致状态缺失。

Linux CI 另行运行原生 hud-state-tests 验证合法 JSON、错误根类型、错误 rows、错误 visible 类型、缺字段；编译、ELF64/x86_64、ldd、readelf、GLIBC <= 2.31、安装 ZIP 结构与隔离导入全部通过后才上传。最终 CI 状态见 v0.2.0 Release，本文不预先声称尚未运行的构建成功。

## 未验证和限制

- 缺少真实设备日志，特别是 Decks.log 格式变化、断线重连、回溯/特殊替换整副卡组、部分未知牌洗回的场景；日志不足时保持“部分已知/未知”，无法保证所有卡牌机制都能完整重建。
- 持续 5 分钟无日志更新会切换等待，长时间暂停可能触发此行为；不是游戏进程生存状态检测。
- 不支持战棋/佣兵记牌，识别到对应 GameType 显示“不支持的模式”；不实现竞技场评分/自动选牌或互动悬浮。
- 不自动编辑 log.config；诊断与配置启用分别处理。
- 实际新版面板位置、字体大小、卡图网络可达性、游戏内记牌准确性与性能仍需 Ally X 验收。v0.1.x 的已验证显示协议不等于 v0.2.0 新内容验收。
