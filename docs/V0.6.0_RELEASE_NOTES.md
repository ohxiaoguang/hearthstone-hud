# Hearthstone HUD v0.6.0

竞技场已选牌改为完全由游戏内存中的 `DraftDeck` 提供，日志不再参与计数。修复了“点击候选查看详情被当成多次选牌”导致的重复计数。

## 主要变化

- **唯一数据源**：已选牌只来自 `DraftManager.m_draftDeck`（地下模式为 `m_undergroundDraftDeck`）的 `m_slots`（`m_cardId` + `m_count`）。重复卡按实际份数显示，候选永不进入已选牌。
- **不再重复计数**：同一张卡连点 N 次只会写 N 条日志，已选牌数量不变。手工补录与 Decks.log 最终定义同样不再影响已选牌。
- **快照整体替换**：每份内存快照替换上一份，不做增量追加；数量就是 `len(state.deck)`。
- **费用排序**：已选牌按 `cost` 升序，同费按名称排序，费用未知的排在最后；排序不增删卡牌。
- **HUD 简化**：右侧只有一个「已选牌 X/30」列表，去掉“日志/确认顺序”“内存历史 · 顺序未知”“重选操作”等分区与来源提示。候选区、卡图、费用与评分保持不变。
- **过期提示**：读取正常时标题是「已选牌 X/30」；读取失败但保留上一份快照时变为「已选牌 X/30（份数待确认）」，下一次成功读取自动消失。读取成功但当前没有进行中的选牌（已选满、切页）不会误报。
- **异常处理**：同一进程同一竞技场读取失败时保留上一份牌组（不回退日志）；游戏退出、进程实例变化、竞技场 ID 变化或回到英雄选择时清空；`REDRAFTING` 以当前内存牌组替换。

## 移除

- `engine/arena_recovery.py`（日志与内存合并、历史恢复、锚点/窗口、不确定标记）及其 39 项测试。
- QAM 里未挂载的竞技场手动候选/补录页面（`src/arena.tsx`）。
- `Arena.timed_records()`。

`Arena.log` 仍会解析（日志面板与诊断可用），`Power.log` 普通对局记牌与 `Decks.log` 的最终牌组绑定均未改动。

## 验证

- Python：188 项测试通过（`python3 -m unittest discover -s tests`）。
- 原生状态测试：`backend/state_test.cpp`（含 `arena_rows` 平铺与 `arena_picked_title` 三种标题断言）。
- 前端：`npm run typecheck`、`npm run build`、剪贴板与折叠控件检查通过。
- Linux 渲染器（Ubuntu 20.04 / glibc 2.31）与插件 ZIP 打包、`py_modules` 导入校验由本次 Actions 构建完成。

## 安装

下载 `hearthstone-hud-0.6.0.zip`，在 Decky Loader 中通过「从文件安装」选择该 ZIP。渲染器只支持 Linux / SteamOS（x86_64）。

## 已知限制

- 内存布局限定 Unity 6000.3 x64 / `mono-2.0-bdwgc.dll` / Assembly-CSharp，不符时报告不兼容而不猜测。
- 没有内存读取就没有已选牌（本版不再有日志兜底），这是刻意取舍。
- 快照刷新约 500ms，选牌后数量最多延迟一次轮询。
- 同费卡按名称的字符串字典序排列，不是拼音序。
